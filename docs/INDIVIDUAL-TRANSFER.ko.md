# 한 마리 전송 / 교환 설계 (3.5.0)

## 안전성 경계

`trade.cpp`는 기존 UDP/ESP-NOW 전송 위에서 별도 메시지 80, 규격 1을 사용합니다. 양쪽의 난수 64비트 제안 번호가 거래 식별자가 되며 상대 번호와 데이터 식별값이 맞지 않으면 진행하지 않습니다. 72바이트 개체 정보를 범위 검사하고 수신 측 그림을 확인한 뒤 사용자 승인을 받습니다. 기존 배틀용 LinkMon은 개체값·돌봄 정보를 모두 담지 않으므로 전송 개체로 사용하지 않습니다.

단계는 OFFER → MATCH → READY → COMMIT → APPLIED → DONE입니다. 자기 번호가 작은 기기가 결정권자입니다. 양쪽 READY를 확인한 결정권자가 COMMIT을 영구 저장한 뒤에만 상대가 적용할 수 있습니다. 각 단계는 확인 읽기와 플랫폼 영구 저장 이후에만 전송됩니다. Android/PC는 원자적 파일 체크포인트의 성공을 기다리고, ESP는 NVS와 기존 SD 이중 보관 스냅샷을 사용합니다.

적용은 선택한 칸의 원래 개체와 수신 개체를 모두 보관한 저널을 기준으로 합니다. 재시작 때 칸이 원래 값이면 수신 값으로 변경하고, 이미 수신 값이면 재삽입하지 않습니다. 어느 쪽도 아니면 오류로 잠급니다. 받은 도감 등록도 다시 적용해도 중복 계산되지 않습니다.

완료/취소 영수증을 영구 저장한 뒤에만 보관 잠금을 해제합니다. 늦은 재전송에는 이전 결정을 답하고, 상대가 영구 종료 상태를 보이면 영수증을 비웁니다. 미확인 기록은 최대 32건으로 제한하며 강제 폐기하지 않습니다. 확정 전 취소는 원본을 보존하며, 확정 뒤에는 상대와 재연결해야 합니다. 두 기기가 동시에 항상 완료를 알게 되는 것은 보장하지 않으며 무한 단절에서 임의 롤백하지 않습니다.

`txJournal` / `txReceipts`는 해당 기기에만 속합니다. 전체 세이브 필드표에 넣지 않으며 진행 중에는 백업·복원을 거부합니다. 기존 72바이트 개체와 v7 백업은 변경하지 않습니다. 거래가 없는 기존 저장은 빈 로컬 거래 상태로 시작합니다. 구버전 실행 중의 미완료 거래 보호는 지원하지 않으므로 거래 중 다운그레이드하지 않습니다.

## 검증 범위

`trade_test`는 서로 독립된 두 RAM/영구 저장을 번갈아 구동합니다. 손실 패킷, 양쪽 승인, 300번째 박스 선물, 취소, 확인 이후 취소 금지, 재시작, 체크포인트 실패, 영구 기록 다섯 지점의 강제 전원 차단, 보관 쓰기 실패 및 복구, 잘못된 역할/개체 정보, 백업 분리를 확인합니다.

`trade_ui_test`는 실제 스케치의 메뉴·대상 선택·정보 확인·확정·스와이프와 가득 찬 수신 공간을 확인합니다. 실제 기기 간 무선, 기기 강제 종료와 SD 물리적 전원 차단 시험은 별도입니다.

## 제한

서버 인증·인터넷 매칭·통신 진화·알 교환은 없습니다. 기존 전체 백업의 고의 복원이나 악의적인 수정 기기를 완전히 막는 부정행위 방지 시스템은 아닙니다. 가까운 신뢰하는 상대와 확인 코드를 대조해 이용합니다.

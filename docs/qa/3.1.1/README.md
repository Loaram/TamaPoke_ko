# 3.1.1 저장 복원 패치 검증

## 원인과 변경

Android와 PC의 NVS 파일 판독기는 값 길이 4,096바이트 초과 시 반복문을 중단한 뒤 부분적으로 읽은 데이터만 적용했습니다. 현재 `rosterF`는 22,116바이트이고 파일 키 순서상 `sleep`, `slpa`, `snd`, `vol`보다 앞에 있어 박스 및 이후 설정 복원이 누락되었습니다. 메모리 Preferences만 사용하는 기존 검사는 이 파일 경계를 통과하지 않았습니다.

Android/Wear와 PC가 공통 NvsFile을 사용하도록 변경했습니다. 파일 규격은 그대로이며 값 최대 64KiB·파일 최대 1MiB·1,024키·키 64바이트의 범위를 검사합니다. 잘린/중복 키/초과 길이/후행 쓰레기 데이터는 거부하고 원본을 덮어쓰지 않습니다. 쓰기는 임시 파일 동기화와 닫기 성공 후 교체하며 실패한 상태는 dirty로 남깁니다. Android는 읽기 실패 시 안내 후 종료합니다.

## 검사와 증거

- `runtime.log`: 48개 전체 실행 검사. `nvs_file`은 실제 파일의 큰 값·이후 설정·기존 소형 기록·빈 값·원자적 덮어쓰기·손상 거부·저장 재시도를 확인합니다.
- `android_lifecycle`은 실제 300칸 박스 저장 후 메모리를 비우고 다시 읽습니다. 음소거/음량 3, 직접 재운 상태, 첫 칸과 마지막 칸, 오프라인 2분 활력 20→36, 추가 재개 2분 36→52와 중복 재개 무시, 직접 깨운 후 재시작을 검사합니다.
- `sd-store.log`: 기존 ESP 저장 실패 모의 검사 10개.
- `static-checks.log`: 한국어·9세대·폼·설치 페이지 검사.
- `android.log`, `wear.log`, `esp.log`, `emu.log`, `dex.log`, `shiny.log`: 각 플랫폼 빌드. Android 3020 / Wear 3021이며 기존 서명을 유지합니다.
- `build-results.json`: 공개 자산 6개와 비공개 도감 에뮬레이터 해시·크기, 저장 규격 및 데이터 유지 검증.
- `guide-contact-*.png`: 최신 플레이 PDF 24쪽을 렌더링해 전체 검토했습니다. 변경된 기본 조작 4쪽은 원본 크기로도 확인했습니다. 워치 설치 PDF는 원본과 바이트가 같습니다.

## 한계

실제 휴대전화·워치·ESP 설치/전원 차단/무선은 미검증입니다. 호스트에서 APK와 동일한 파일 판독/저장 코드 및 Android 생명주기 로직을 검사했으며 실제 AAudio 재생이나 Android OS 강제 종료 시험을 대체하지 않습니다. 이전 버전이 이미 덮어쓴 손실 정보는 복구하지 못합니다. ESP 파티션·SD 저장·저장 v7/프로토콜 5·밸런스는 변경하지 않았습니다.

# 연속 돌봄 기록 손실 추가 조사

2026-09-06, 3.1.1 정식 배포 후 사용자가 3.0.0에서 박스 포켓몬을 데려온 뒤 연속 기록이 끊긴 것 같다고 보고한 건을 조사했습니다. 사용자 실제 세이브나 화면은 제공되지 않았으므로 개별 기기의 정확한 발생 이력까지 확정한 것은 아닙니다.

## 재현된 원인

3.0.0 커밋 `4fc1def`의 Android 파일 판독기는 4,096바이트를 넘는 값을 만나면 중단합니다. `rosterF`는 22,116바이트이고 뒤에 있는 `strk`(현재 연속 일수)는 읽히지 않습니다. 앞쪽의 `bstrk`(최고 기록)와 `cday`(마지막 돌봄 날짜)는 읽힙니다. 이 현상은 Android/Wear 및 당시 같은 제한을 사용한 PC 판독기에 해당하며 ESP32의 NVS/SD 판독기는 해당 경로를 사용하지 않습니다.

실제 돌봄을 10일 수행하고 박스 마지막 칸 포켓몬을 데려온 상태를 파일로 저장하여 비교했습니다.

| 상황 | 현재 / 최고 | 마지막 돌봄 날짜 |
|---|---|---|
| 박스 교체 전후 | 10 / 10 | 유지 |
| 3.0.0 판독기로 재시작 | 0 / 10 | 유지 |
| 위 상태에서 당일 다시 돌봄 | 0 / 10 | 당일 중복이라 증가하지 않음 |
| 위 상태에서 다음 날 돌봄 | 1 / 10 | 다음 날로 갱신 |
| 동일한 원본 파일을 3.1.1로 재시작 | 10 / 10 | 유지 |
| 3.1.1에서 다음 날 동료 돌봄 | 11 / 11 | 정상 갱신 |

따라서 박스 교체 함수가 플레이어의 연속 일수를 초기화한 것은 아닙니다. 큰 박스 기록이 포함된 파일의 재시작 복원에서 기록을 잃는 오류이며, 박스 교체를 하지 않아도 같은 조건에서 발생할 수 있습니다.

## 수정·배포 상태

파일 판독기의 부분 복원 오류는 이미 정식 **3.1.1 (`d7bf7a4`)**에서 수정·업로드되었습니다. 이번 조사에서는 게임 규칙이나 APK를 다시 변경하지 않았으며 **새 버전을 발행하지 않습니다**. 3.1.1 APK·Wear APK·ESP32 파일 및 두 PDF는 그대로 유지합니다.

회귀 검사 `streak_persistence`를 추가했습니다. 과거 판독기는 오직 테스트 내부 재현용이며 제품에 포함되지 않습니다. 현재 판독기로 박스 교체·당일 돌봄·다음 날 돌봄·교체 중단 후 복구·전체 세이브 전송이 현재/최고/날짜를 보존하는지 검사합니다. 실제로 하루를 빠뜨렸을 때 1일차로 돌아가는 기존 규칙도 유지합니다.

- `streak-reproduction.log`: 새 재현 검사 통과.
- `streak-related.log`: 기존 active_swap, daily_rewards, android_lifecycle, nvs_file 검사 재실행 통과.
- 자동 검사 목록은 기존 48개에 새 검사 1개를 더한 49개입니다. 원래 3.1.1 배포 기록의 48개 결과는 당시 결과로 보존합니다.

## 이미 끊긴 기록

업데이트는 앞으로의 누락을 막지만, 구버전이 이미 0이나 1로 덮어쓴 일수를 자동으로 되살리지는 않습니다. 최고 기록은 현재 연속 일수와 다를 수 있으므로 최고 기록을 현재 기록으로 임의 복사하지 않습니다. 복원을 검토하려면 손실 전 백업 등 근거가 필요합니다.

3.1.1에서 새로 시작한 연속 기록도 계속 끊기거나 ESP32에서 발생했다면, 기기·버전·발생 전후 현재/최고 기록·날짜와 실제 세이브를 바탕으로 별도 조사가 필요합니다. 실기 설치·전원 차단은 이번에도 시험하지 않았습니다.

# 3.9.1 연속 돌봄·달력 회귀검사

## 원인과 수정

ESP의 RTC 초기 날짜와 폰의 날짜가 다른 상태에서 `seen`만 현지 시각으로 바뀌고 `cday`·일일 제한·보관 개체의 날짜가 남으면 연속일수가 멈추거나 초기화될 수 있었다. 저장 v7에 선택 키 `dayOff`를 추가하고 전체 세이브 적용 시 수신 기기 달력을 원본의 논리 날짜에 정렬한다. 개체 72바이트와 누적 수치·일일 사용량은 변경하지 않는다.

폰 → ESP → 폰 왕복에서는 과거 Android UTC(`aseen`)를 재사용하지 않고 새 기준을 잡는다. 무효/후퇴 RTC는 마지막 저장 시각에서 재개하고, 자정 첫 행동 전 시각을 갱신한다. 보관 교체용 임시 Pet의 lastCareDay 누락으로 당일 유대 한도가 다시 채워지는 경로도 수정했다.

## 실제 게임 코드로 검사하는 시나리오

- 과거·미래·같은 날짜로 전체 세이브 적용, 각 8회 왕복
- 연속 10일/보너스 유지, 알 2회 소진 및 유대 20 사용량 유지
- 300번째 박스 개체의 바이트 불변과 실제 데려오기, 저장 비교/복구
- 다음 수신 기기 자정은 11일, 실제 하루를 빠뜨리면 1일로 정상 처리
- 재시작, 구버전 미래 cday 한 번 복구, RTC 초기화·후퇴·정상 전진
- 손상 입력/무효 시각 거부, dayOff 쓰기 실패 시 원본 전체 롤백
- 전달된 Android UTC 기준 해제: 이미 적용된 성장 시간 중복 재생 방지

`calendar-final.log`는 최종 코드의 집중 5종 검사, `runtime.log`는 전체 67종 검사다. `build-results.json`은 공식 공개 파일의 크기·SHA-256, 서명·그림 팩·ABI·가이드·워치 동봉 APK 일치 검사를 기록한다. 최종 커밋의 GitHub Actions 성공을 별도 공개 조건으로 둔다.

플레이 가이드31쪽과 워치 도우미7쪽을 모두 렌더링해 확인했다. 기존 수동 워치 설치 PDF는 변경하지 않았다. 실제 ESP 자정 경계·배터리 분리·장기간 RTC 유지·이번 APK 설치/기기간 전송은 이 자동검사의 대체 대상이 아니며 이번 작업에서는 실기 재검증하지 않았다. 이미 사라진 연속일수를 추측해 복원하지 않는다.

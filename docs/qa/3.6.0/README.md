# 3.6.0 도감 포획 보너스 검증

수집 가능한 등록 도감 100종마다 볼 배율 +0.2, 포획률 3은 2.5%에 같은 배율을 적용한다. 기존 저장·프로토콜과 다른 확률은 변경하지 않는다. 실제 배포 파일의 해시와 최종 판정은 `build-results.json`, 검증 소스와 서버 실행 번호는 `ci-evidence.json`을 기준으로 한다.

## 검사 범위

[배포 전 CI 34109972150](https://github.com/Loaram/TamaPoke_ko/actions/runs/34109972150)이 전체 성공했다. 런타임 59개·SD 장애 10개·500만회 모의 포획을 통과했으며, 최종 게임 소스와 검증 소스의 동일성을 확인했다. 로컬 설치 도우미 30개 검사와 9개 배포 자산 대조도 통과했다.

- `capture_dex`: 포획률 0~255 × 등록 수 0~982의 251,648개 조합을 별도 기준식과 대조한다. 모든 흔들림 판정 경계, 배율 단조 증가와 포획률 3의 1,000개 추첨값을 확인한다.
- 다섯 예시(캐터피 255, 피카츄 190, 단데기 120, 파이리 45, 뮤츠 3) × 10단계 × 10만회 = 500만회 모의 포획. 고정 난수 시드의 독립 균등 분포로 각 단계 기대값의 7표준편차 + 5회 허용 범위를 검사한다. 정확한 확률은 경계 전수검사가 확인하며 표본 검사는 보조다.
- 중복·이로치·그림 미지원 종의 중복 집계 방지, 재시작 및 v7 전송, 99→100종 경계, 실제 배틀 종료의 성공/실패·중복 방지·패배 시 미추첨을 검사한다.
- 전체 런타임은 59개이며 기존 데려오기·훈련 복구·설정·성장·교환·배틀 검사도 포함한다. 별도 SD 장애 검사 10개와 설치 도우미 검사 30개를 실행한다.
- `tools/record_release_360.py`가 실제 C++ 시뮬레이션의 기대값과 Python 가이드 표의 50개 값을 대조한다. 예시 종별 포획률은 게임 데이터와도 대조한다. PDF 29쪽/7쪽 렌더링, APK ABI·기존 서명, 도우미 동봉 APK, 원본 수동 설치 PDF, ESP 설치 범위 및 9개 공개 자산의 검사값을 확인한다.

## 실행 환경과 한계

Windows에서 새 `capture_dex` 실행 파일이 WinError 4551로 차단되어, 보안 설정을 변경하지 않고 별도 검증 브랜치의 GitHub Ubuntu 환경으로 전체 검사를 수행한다. 통과한 CI 소스와 최종 게임 소스의 바이트 동일성을 대조한 후 메인/정식 릴리스에 반영한다. Windows에서 만든 PC·Android·Wear·ESP 빌드는 별도로 확인한다.

실제 휴대전화·워치 설치, 기기 간 무선, 물리적인 SD 전원 차단은 이번 검사 범위가 아니다. 미완료 거래가 있으면 같은 상대와 먼저 끝내고 업데이트 전 세이브를 백업해야 한다.

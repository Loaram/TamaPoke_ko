# 3.6.1 진화 계열 수집 잠금 검증

원인: 알은 `speciesCanHatch()`로 진화 계열 전체를 제외했지만 탐색은 `speciesHasArt()`만 확인했다. 그림이 있는 구르데(953)·하느라기(955) 등을 포획한 뒤 그림 없는 진화형으로 진행할 수 있었다.

## 수정과 검사

[배포 전 전체 CI 34123779952](https://github.com/Loaram/TamaPoke_ko/actions/runs/34123779952)가 성공했다. 런타임 60개, SD 장애 10개, 247,808개 포획 조합, 500만 회 모의 추첨, 에뮬레이터 화면 생성과 ESP 빌드를 통과했다. 최종 게임 소스가 해당 검증 소스와 같은지도 확인했다. 로컬 설치 도우미 30개 검사 및 공식 자산 9개 대조도 통과했다.

- `speciesIsCollectible()`을 탐색과 보너스 집계의 공통 기준으로 사용한다. 그림 미지원 43종과 하위 15종, 총 58종 제외. 총 967종 / 50% 목표 484종.
- `collection_lock`은 일반·분기 진화 그래프에서 미지원 종의 모든 조상을 독립적으로 역추적하여 잠금 목록을 검증한다. 모든 지역·희귀도 후보를 검사해 잠금 종이 나오지 않고 나머지 967종은 도달 가능한지 확인한다.
- 기존 개체와 등록 비트는 보존한다. 잠긴 기존 개체의 진화가 개체/세이브를 바꾸지 않는지, 재로드와 v7 전송이 되는지 확인한다. 보너스 계산의 분자·전국/지역 분모를 함께 검사한다.
- 전체 런타임은 60개이며 포획 247,808개 조합과 500만 회 모의 추첨, 기존 데려오기·훈련·통신·성장·저장 회귀 검사를 포함한다.
- APK 2종의 기존 서명/버전 코드/리소스, ESP 펌웨어, Windows 워치 도우미 30개 검사와 동봉 APK/PDF 검사값, 플레이 PDF 29쪽·설치 도우미 PDF 7쪽을 대조한다.

## 환경과 한계

Windows에서 `collection_lock` 및 `capture_dex`는 통과했으나 이후 `recovery_clock.exe`는 Smart App Control의 WinError 4551로 차단됐다. 개별 예외를 지원하지 않는 정책이므로 전체 보안을 끄지 않고 GitHub Ubuntu에서 전체 검사를 확인한다. 서버 실행 결과와 최종 코드 동일성 및 자산 검사값은 `ci-evidence.json`, `build-results.json`에 기록한다.

실제 휴대전화/워치 설치·무선·물리적 전원 차단은 시험하지 않았다. 기존 세이브를 백업하고 미완료 교환을 먼저 완료한 뒤 덮어 설치해야 한다.

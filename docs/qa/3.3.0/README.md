# 3.3.0 탐색 결과창 검증

## 원인과 수정

기존 전투 메시지 큐는 6개, 화면 출력은 앞 4줄이었습니다. 마지막 턴 메시지가 많으면 5~6번째 포획 결과가 보이지 않고 battleTap이 큐 전체를 지워 함께 사라졌습니다. 결과를 큐에서 분리한 뒤 확인 버튼으로만 닫는 별도 창을 사용합니다. 성공·파티/박스 목적지, 포획 실패, 패배 시 미시도, 보관 검증 오류를 구분합니다.

결과는 한 번만 결정합니다. 표시 전 입력, 450ms 입력 보호, 창 바깥 터치와 가로·세로 스와이프 차단을 적용합니다. 성공 보관은 확인 전에 완료되며 다시 그리기·반복 종료 호출로 재추첨/중복 저장되지 않습니다. 불확실한 보관 쓰기 실패 뒤 다른 목적지로 재저장하지 않습니다.

## 검사

- `runtime.log`: 전체 51개. 새 `wild_result`는 위 다섯 결과, 정확한 개체·이로치 도감·목적지, 저장 재로드, 중복 방지, 표시/입력 보호, 실제 기술 버튼→마지막 턴→결과창 연결, 확인 후 다음 탐색과 체육관 분리를 확인합니다.
- `sd-store.log`: SD 실패/복구 10개.
- `static-checks.log`: 한국어·데이터·폼·설치 페이지 검증.
- 각 플랫폼 빌드 로그 및 `build-results.json`: APK ABI/그림 팩/해시, ESP 배포 파일, 695개 기존 기술 ID 불변, 공개 파일 6개, 25쪽 플레이 가이드와 원본 워치 가이드 불변.
- `wild-result-*.png`: 실제 결과창 렌더링(한국어 성공/박스/실패/패배/보관 오류, 영어 실패). 포켓몬 썸네일과 이름, 안내, 버튼 배치를 확인합니다.
- `guide-contact-*.png`: 플레이 PDF 전체 25쪽을 렌더링해 검수합니다. 25쪽에는 결과창과 오류 구분을 추가하고 기존 페이지 번호는 유지합니다.

## 유지 사항과 한계

확률·활력·개체값 등 게임 밸런스, 저장 v7/최대 32,768바이트, TFR3/22,116바이트, 프로토콜 5와 ESP NVS/SD 구성은 변경하지 않습니다. 결과창 상태는 실행 중 UI 상태이며 앱 프로세스를 강제 종료한 뒤 창을 복원하는 기능은 추가하지 않았습니다. 이미 성공한 보관은 저장됩니다.

실제 휴대전화·워치·ESP 설치, 물리적 SD 전원 차단, 기기 간 무선 시험은 실시하지 않았습니다. 테스트용 도감 해금/이로치 해금 에뮬레이터는 공개 자산에 포함하지 않습니다.

# 3.4.0 파티 생존 판정과 이로치 검증

## 원인과 수정

`btlResolve`는 현재 인덱스 뒤에 칸이 있는지만 확인했고, 자동 교체는 인덱스를 1 증가시켰습니다. 수동 교체로 마지막 칸을 내보내면 앞쪽 생존 동료를 놓쳤고, 뒤쪽 칸의 포켓몬이 이미 쓰러졌는지도 확인하지 않았습니다.

`btlNextAlive`는 활성 칸을 제외한 모든 칸을 순환하며 살아 있는 동료를 찾습니다. 활성 칸의 오래된 HP 사본을 생존으로 오인하지 않습니다. 실제 교체 시 쓰러진 현재 개체를 기록하고, 찾은 동료의 HP/상태를 그대로 가져옵니다. 양 팀의 생존 여부를 먼저 판정하여 동시 기절에서 잘못 끝내거나 살아 있는 상대를 두고 승리하는 경로도 제거합니다. 근거리 결과 전송을 턴 종료 피해 이후로 옮기고 자동 교체 완료 때 절대 위치/HP를 전달합니다. 추가 공격은 실행하지 않습니다.

탐색 이로치는 편향 없는 1/100 판정입니다. 새 알의 이로치 여부를 종보다 먼저 정하고 이로치 알만 일반 도감 미획득 우선을 건너뜁니다. 기존 대기 알·보너스·저장 규격은 유지합니다.

## 검사 자료

- `runtime.log`: 전체 53개 런타임 묶음.
- `focused.log`: 실제 기술 버튼 경로로 파티 활성/생존 위치 30조합, 모든 동료 기절, 근거리 양쪽 교체·전송, 독 동시 기절, 양 팀 생존 판정과 실제 체육관 시작을 확인합니다. 이로치 알 및 별도 포획 결과창 검사도 포함합니다.
- `sd-store.log`: SD 저장 실패와 복구 모의 검사 10개.
- `static-checks.log`: 한국어·데이터·폼·설치 페이지 검사.
- 플랫폼 빌드 로그와 `build-results.json`: APK ABI/그림 팩/해시, ESP 파일, 기존 기술 번호, 6개 배포 자산, 플레이 PDF 25쪽 및 원본 워치 가이드 불변 검사.
- `guide-contact-*.png`: 최종 플레이 PDF 전체 페이지 렌더링 검수.

Windows에서 이전 검사 실행은 Smart App Control로 차단됐으나 이번 빌드의 로컬 검사 실행은 가능했습니다. 보안 설정은 변경하지 않았습니다. 실제 기기 설치, 기기 간 무선 및 물리적인 SD 전원 차단은 실시하지 않았습니다. 저장 v7/32,768바이트, TFR3/22,116바이트, 무선 프로토콜 5와 기기별 저장 구조는 유지합니다.
